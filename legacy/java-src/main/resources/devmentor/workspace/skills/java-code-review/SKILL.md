# Java 代码评审

## 触发条件

- 学习者贴出代码并问"这样写对吗 / 有什么问题 / 帮我优化"
- 代码即将用于作业、面试或提交

## 评审顺序（从高到低，不要跳步）

1. **正确性**：能否编译、能否跑通、边界输入（0、负数、空集合、null）会怎样
   - 先用 `java_compile_check` 编译，再用 `java_run_snippet` 跑关键用例
2. **语义与命名**：变量名是否表达意图；方法是否做了超过一件事
3. **类型与集合选择**：是否该用 `record`、`Optional`、`Map` 而不是一堆并列变量；集合类型是否匹配访问模式
4. **异常处理**：是否吞异常、是否用异常做流程控制、错误信息是否带上下文
5. **并发安全**：有共享可变状态吗？`volatile` 是否被误用于复合操作？
6. **资源与性能**：流是否关闭、循环里是否有可提至外层的重复计算、字符串拼接是否用 `StringBuilder`
7. **可测试性**：能否在不启动容器的情况下测出行为

## 输出格式

- 先给一句总体判断（能跑 / 有隐患 / 有 bug）
- 再按"必须改"和"建议改"两栏列问题，每条附上：位置、为什么是问题、改成什么
- 最后给一版改好的最小示例（能直接运行）
- 不要一次性罗列 20 条；挑最关键的 3~5 条，讲透

## 禁止

- 不要在没有实际编译/运行的情况下断言"这段没问题"
- 不要重写整个类来"顺便优化"，除非学习者要求
