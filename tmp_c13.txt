fix: 会话 id 在 Python 3.12 下会全部相同，加进程内序号兜底

跨版本验证（3.12 vs 3.13）抓到的问题，Windows + 3.13 下完全看不出来。

现象：连续生成 20 个会话 id，
  3.13 -> 20 个唯一值
  3.12 -> 1 个唯一值（全部相同！）

根因：Python 3.12 在同一进程里连续调用 datetime.now() 时，微秒部分
不前进（时钟粒度未刷新）。而 id 只靠 "年月日-时分秒-微秒"，于是
同一微秒内连开两个会话就撞名。

后果不轻：/new 之后新会话的 id 与旧会话相同，save_state 会覆盖
旧会话文件——用户以为开了新会话，实际历史被静默冲掉。

修复：id 末尾加进程内自增序号，格式变为
  mentor-YYYYMMDD-HHMMSS-微秒-序号
自增序号不依赖时钟，因此任何版本下都唯一。

实测（修复后）：
  3.13 -> 20/20 唯一
  3.12 -> 20/20 唯一
  连开 50 个会话 -> 磁盘 50 个不同文件

同时验证了 Python 3.12 下整套测试通过（187 项），没有其它版本差异。
